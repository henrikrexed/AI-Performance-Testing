Knightload turns the traces, logs, and sessions you already collect into a realistic load test — one you can read, diff, and trust. Stop hand-writing scenarios that guess at how users behave. Load from reality.

Get startedRead the methodology

Most load tests are educated guesses.

Someone writes a script: a few endpoints, a round number of virtual users, a flat ramp. It passes. Production still falls over — because the script never looked like the real thing. The journeys were invented, the pacing was a guess, the mix was a hunch.

KnightLoad starts from the opposite end. The workload you want to replay has already happened, and your observability backend recorded it: which request chains are common, how they split across user types, how fast traffic actually arrives, how long real users pause between steps. KnightLoad extracts those facts into a workload model, a human signs off on it, and only then does it become a running test.

You don’t describe the load. Your telemetry does.

One loop, five stages, a gate on every hand-off.

SCOPE extracts the model, a human approves it at the V1 gate, and only then does it become a running, analyzable test.

Why it’s different

Realism is measured, not guessed.

Journeys, arrival rates, and think-times are derived from your own telemetry — spans, access logs, RUM sessions, and OTel session.id. Nothing is assumed where a number can be extracted.

A human gate is mandatory.

No test runs against any environment until a person reads the proposal and approves the workload model (Gate V1). Approval is bound to the exact model revision; edit the model and the approval is void.

Tests are code you can read.

Every generated test is committed, diffable, and reviewable. Regeneration is deterministic given the same model and seed — no black-box recorder, no artifact you can’t inspect.

Synthetic traffic stays identifiable.

Every generated request carries synthetic=true baggage, promoted to a queryable attribute. Your test traffic and your real traffic never blur — even when they share an environment.

One approved model. Four load tools.

KnightLoad separates what to replay from what runs it. Once your workload model is approved, render it to the load tool your team already uses. Every renderer reads the same model as its only contract, and each one honestly declares where it approximates.
