Installing the skills

The skills/* directories follow the agentskills.io convention: each is a directory with a SKILL.md (the instructions the agent loads) plus deterministic scripts and tests. An agent "installs" a skill by having its directory on the agent's skills search path.

Skills in this repo:

SkillStageWhat it does
workload-modelSCOPEtelemetry extract → G0-gated workload-model.json + proposal
k6-synthesis · jmeter-synthesis · locust-synthesis · gatling-synthesisSYNTHESIZEapproved model → runnable test (one renderer-kit interface)
loadtest-runEXECUTEscoped run: allowlist, hard caps, auto-abort, run report
baseline-diffANALYZEDQL shape-diff vs. baseline, accept / iterate / escalate
rum-sessions · session-stitchSCOPE (RUM)RUM session shape & ordered-action reconstruction

Which renderers ship today: k6-synthesis is bundled and wired end-to-end (the guided flow generates a runnable k6 project headlessly). jmeter/locust/gatling follow the same one-interface renderer-kit contract; install their synthesis skills the same way and the guided flow hands them the approved model. Pick your renderer in the guided flow's step 2.

Quickstart — two commands​

No manual symlinking. One command installs the skills into your coding agent; the second is the first prompt that starts the guided loop.

# 1 — fetch the repo and install the skills into ~/.claude/skills (verifies them)
curl -fsSL https://raw.githubusercontent.com/henrikrexed/AI-Performance-Testing/main/install.sh | sh

install.sh clones the repo (or downloads a tarball when git is absent) and runs engine/cli.py init, which copies every bundled skill into your agent's skills directory and verifies each one loads. The default destination is ~/.claude/skills (the Claude Code user-wide path); override with --dest or AIPT_DEST. From an existing checkout the no-curl equivalent is:

git clone https://github.com/henrikrexed/AI-Performance-Testing.git
cd AI-Performance-Testing
python3 engine/cli.py init                       # -> ~/.claude/skills, then verifies
python3 engine/cli.py init --dest .agents/skills # cross-client location instead

init prints the exact next command. The second command of the quickstart is that prompt — start the guided 4-step flow (see engine.md §3):

# 2 — drive the gated loop on the bundled synthetic example (no backend needed)
python3 engine/cli.py guided \
    --extract examples/crewai-deepseek-agent/extract.json \
    --out ./out --mode agentic

…or, with an agent that now has the skills, just ask in plain language:

"Use the workload-model skill to build a model from the example extract."

That is the whole onboarding. The manual per-agent copy steps below remain for CI, locked- down boxes, or agents whose skills directory differs from the defaults.

Manual install (per agent)​

Each coding agent discovers skills from a conventional directory. Install = copy (or symlink) the skill directory there. Paths below follow the same standard the Dynatrace CLI uses (dtctl skills install --list).

git clone https://github.com/henrikrexed/AI-Performance-Testing.git
cd AI-Performance-Testing

Claude Code​

# project-local (this project only)
mkdir -p .claude/skills
cp -r skills/* .claude/skills/

# or user-wide (all projects)
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/

Claude Code auto-discovers every ~/.claude/skills/<name>/SKILL.md (or the project-local .claude/skills/) and loads a skill when the task matches its description.

opencode​

# project-local
mkdir -p .opencode/skills
cp -r skills/* .opencode/skills/

# or user-wide
cp -r skills/* "$HOME/.config/opencode/skills/"   # --global location

Cursor​

# project-local (Cursor discovers project skills, not user-global ones)
mkdir -p .cursor/skills
cp -r skills/* .cursor/skills/

Any agentskills.io-compatible agent (cross-client)​

The portable location — discovered by any compatible agent (Claude Code, opencode, Cursor, Copilot, Kiro, Junie, …) without per-agent copying:

# project-local
mkdir -p .agents/skills
cp -r skills/* .agents/skills/

# or user-wide
mkdir -p ~/.agents/skills
cp -r skills/* ~/.agents/skills/

Verify​

Ask your agent to run the bundled worked example — if the skill is installed, it will pick it up by name:

"Use the workload-model skill to build a model from skills/workload-model/fixtures/example_extract.json."

Or run a skill's tests directly to confirm the files are intact:

( cd skills/workload-model && python3 -m pytest -q )        # 68 passed
( cd skills/k6-synthesis   && node --test test/*.test.mjs ) # 51 passed

Installing these skills is separate from installing the dtctl agent skill (which ships with the CLI via dtctl skills install). See requirements.md §3.
